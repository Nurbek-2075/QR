# Учёт посещаемости по QR-коду

Веб-приложение для учёта посещений. Администратор показывает временный QR-код, участник сканирует его и отмечает присутствие. Интерфейс и логика приложения находятся в одном файле — [index.html](./index.html).

## Возможности

- Вход и регистрация участника по логину и паролю. Логин приводится к нижнему регистру; допустимы латинские буквы, цифры, точка и подчёркивание, длина — не менее 3 символов. Пароль при регистрации — не менее 8 символов.
- Для Supabase логин преобразуется в служебный адрес вида `логин@attendance.local`. В базе остаются поля `email` и `owner_email`.
- Локальный режим с хранением данных в `localStorage` браузера.
- Панель администратора с разделами «Главная», «QR-код», «Участники», «Посещаемость», «KPI и отчёты», «Администраторы» и «Настройки».
- Главная панель: пять показателей, график за неделю и таблица последних отметок.
- Статусы «Пришёл», «Опоздал» и «Отсутствует». Отсутствие определяется по участникам без отметки за выбранную дату.
- Ручное добавление и снятие отметки, поиск по имени и логину, редактирование участников.
- Импорт участников из Excel и экспорт участников и посещений. При импорте поддерживаются заголовки «Имя» и «Логин», а также совместимые колонки `name`, `login`, `email` и `e-mail`.
- KPI за последние 26 недель.
- Роли администраторов. Обычный администратор управляет только участниками с его `owner_email`; главный администратор (`is_main`) видит всех участников. Для главного администратора есть отдельный обзор с карточками и таблицами по администраторам и участникам.
- Светлая и тёмная темы.
- QR-код автоматически обновляется каждые 2 минуты. Есть обратный отсчёт, полноэкранный режим и скачивание PNG.
- Экран результата отметки для участника, кабинет с процентом посещаемости и историей.

## Работа с приложением

### Администратор

1. Войдите по выданному логину и паролю.
2. В разделе «QR-код» покажите участникам действующий код.
3. В разделе «Посещаемость» выберите дату, просмотрите отметки или добавьте отметку вручную.
4. В разделе «Участники» добавляйте участников по имени и логину, редактируйте их или импортируйте список из Excel.
5. Скачайте отчёт Excel из раздела участников, посещаемости или KPI.
6. Главный администратор дополнительно видит раздел «Главный админ» с числом администраторов, участников и отметок за сегодня, статистикой администраторов и таблицей участников.

### Участник

1. Откройте ссылку из QR-кода.
2. Войдите по логину и паролю либо создайте аккаунт с логином, который добавил администратор.
3. При действующем QR-коде посещение отмечается автоматически. Повторная отметка в тот же день отклоняется.
4. В кабинете доступны процент посещаемости и история отметок.

## Демо-аккаунты локального режима

- Главный администратор: логин `admin`, пароль `QRadmin-2026!`.
- Участник: логин `student`, пароль `Student-2026!`.

Это демонстрационные данные. Перед рабочим запуском удалите или замените их в `index.html` и задайте новый пароль главного администратора.

## Ограничения локального режима

При `LOCAL_MODE = true` данные хранятся только в `localStorage` текущего браузера и не синхронизируются между устройствами. Для проверки QR-отметки с телефона нужны одновременно подключённый Supabase и размещённый в интернете сайт с публичным HTTPS-адресом. Прямое открытие `index.html` с диска не создаёт доступную телефону ссылку.

Локальный режим предназначен для разработки и демонстрации. Пользователь с доступом к браузеру может изменить его локальные данные.

## Подключение Supabase

### 1. Создайте схему

Создайте проект Supabase и выполните [supabase_schema.sql](./supabase_schema.sql) в SQL Editor. Схема создаёт:

- расширение `pgcrypto` для генерации UUID;
- таблицы `allowed_admins`, `participants`, `qr_tokens` и `checkins`;
- совместимые колонки `participants.email`, `participants.code`, `participants.owner_email` и `checkins.status`, если их ещё нет;
- ограничения уникальности для логина участника, кода и пары «участник — дата посещения»;
- функции `is_admin()`, `is_main_admin()`, `check_in_for_user()` и `participant_attendance_rate()`;
- включение RLS и политики доступа для всех четырёх таблиц.

`is_admin()` и `is_main_admin()` сверяют служебный адрес из JWT с `allowed_admins`. Администраторы могут читать этот список; добавлять и удалять записи может только главный администратор, причём политика не позволяет ему удалить запись с `is_main = true`. Обычный администратор читает и меняет только участников, у которых `owner_email` совпадает с его служебным адресом, и связанные с ними отметки. Главный администратор видит всех. Участник может читать только собственную запись и историю; QR-токены доступны администраторам.

SQL-функция `check_in_for_user()` проверяет срок действия QR-токена и повторную отметку в текущий день, затем создаёт запись со статусом `present`. `participant_attendance_rate()` возвращает процент посещаемости по датам, в которые в системе есть отметки.

Схема не создаёт пользователей Supabase Auth, не добавляет начальную запись в `allowed_admins` и не назначает владельца старым участникам автоматически. Новые участники получают `owner_email` при добавлении или импорте. Если в существующей базе есть участники с пустым `owner_email`, назначьте им владельца вручную от имени главного администратора.

### 2. Настройте Supabase Auth

1. В Supabase откройте **Authentication → Providers → Email** и выключите **Confirm email**. Служебные адреса `@attendance.local` не предназначены для получения писем.
2. В **Authentication → Users → Add user** создайте главного администратора с адресом `admin@attendance.local`, задайте пароль и включите **Auto confirm**.
3. Добавьте его в `allowed_admins` как главного администратора:

```sql
insert into public.allowed_admins(email, is_main)
values ('admin@attendance.local', true);
```

При добавлении следующего администратора создайте ему пользователя в Supabase Auth с адресом вида `логин@attendance.local`. Затем главный администратор добавляет тот же логин в раздел «Администраторы» приложения. Приложение добавляет запись доступа, но не создаёт пользователя Supabase Auth и не задаёт ему пароль.

### 3. Подключите приложение

В [index.html](./index.html) замените заглушки на значения из **Project Settings → API** и установите `LOCAL_MODE = false`:

```js
const LOCAL_MODE = false;
const SUPABASE_URL = 'https://your-project.supabase.co';
const SUPABASE_KEY = 'YOUR_ANON_PUBLIC_KEY';
```

В HTML можно указывать только публичный `anon`-ключ. Никогда не помещайте туда `service_role`.

Чтобы проверять QR с телефона, разместите сайт на доступном из интернета HTTPS-адресе. Забытого пароля в интерфейсе приложения не сбросить: восстановите или смените его вручную через Supabase Auth.

## Чеклист перед запуском

- Удалить или заменить демонстрационные логины и пароли.
- Установить `LOCAL_MODE = false` и проверить URL и публичный ключ Supabase.
- Сменить пароль главного администратора.
- Проверить RLS-политики на тестовых аккаунтах обычного и главного администраторов.
- Провести репетицию с 3–5 участниками, включая отметку с телефона.
- Сделать резервную копию базы перед переносом реальных данных.

## Публикация в GitHub Pages

Проект не требует сборки: для публикации загрузите `index.html` и `supabase_schema.sql` в репозиторий и включите GitHub Pages. Перед этим подключите Supabase, выключите `LOCAL_MODE` и проверьте приложение по публичному HTTPS-адресу. Закрытый GitHub-репозиторий сам по себе не защищает опубликованный сайт; доступ к данным должен обеспечивать Supabase Auth и RLS.

## Что ещё не сделано

- В проекте включён `LOCAL_MODE`; подключение к реальному проекту Supabase и публикация сайта не настроены.
- В приложении нет формы восстановления пароля.
- Добавление администратора в интерфейсе создаёт только запись доступа в `allowed_admins`; пользователя и пароль нужно отдельно создать в Supabase Auth.
- Статус отсутствия не хранится отдельной записью, а выводится для участника без отметки за выбранный день.
- Отдельного списка мероприятий или расписания занятий нет. Процент посещаемости рассчитывается по датам, когда в базе есть хотя бы одна отметка.
- SQL-схема не заполняет `owner_email` у старых записей, поскольку их прежнего администратора нельзя определить автоматически.
- Автоматические тесты в проекте не добавлены.
